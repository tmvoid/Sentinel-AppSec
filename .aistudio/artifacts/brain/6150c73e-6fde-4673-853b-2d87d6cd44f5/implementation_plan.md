# MLSA KIIT Sentinel — Authentic Security Audit & Vulnerability Verification Platform

An evidence-driven web application built for the **Microsoft Learn Student Ambassadors at KIIT (MLSA KIIT Chapter)** to audit student and chapter web applications, live URLs, and GitHub repositories with zero fabricated findings—reporting only verifiable vulnerabilities backed by raw HTTP responses, exact source lines, or live CVE database records.

## User Review & Critical Decisions

> [!IMPORTANT]
> Every finding generated by this platform is strictly **deterministic and evidence-backed**. The scanner never invents, guesses, or hallucinates vulnerabilities—if a check cannot be verified with concrete proof (raw HTTP header state, verified non-SPA probe match, live OSV.dev CVE record, or exact source code line match), no issue is raised.

- **Confirmed Decision 1 — Official MLSA KIIT Branding & Emblem Integration**: Updated all chapter branding to **MLSA KIIT** (`MLSA KIIT Chapter` / `MLSA KIIT Sentinel`) and integrated the official Microsoft Learn Student Ambassador shield emblem (`/assets/aistudio/image_950b45df.png`) into the top navigation brand lockup, workspace header, and official exportable/printable audit reports.
- **Confirmed Decision 2 — Dual Target Input**: Supports both **Live Deployed URLs** (for HTTP headers, CORS, cookies, TLS, DOM scripts, and exposed sensitive paths) and **GitHub Repositories / Source Code & `package.json`** (via public GitHub URL fetch or direct code/manifest upload).
- **Confirmed Decision 3 — Four Authentic Audit Engines**:
  1. **HTTP Headers, CORS, Cookie & TLS Inspection** (CSP, HSTS, X-Frame-Options, X-Content-Type-Options, Referrer-Policy, Permissions-Policy, Server fingerprinting, Cookie `HttpOnly`/`Secure`/`SameSite`, and live CORS origin reflection/wildcard testing).
  2. **Exposed Env, Sourcemap & Sensitive Route Probing** (non-destructive probes for `.env`, `.git/config`, `package.json`, `robots.txt`, and `.js.map` sourcemaps with SPA catch-all detection so React/Vite `index.html` fallbacks never trigger false positives).
  3. **Dependency CVE Audit via OSV Database** (queries the official `api.osv.dev` vulnerability database against actual `package.json` dependencies and versions).
  4. **Source Code SAST & Hardcoded Secret Detection** (scans repository or uploaded files for leaked API keys/tokens, `dangerouslySetInnerHTML`/`innerHTML` sinks, `eval()`, SQL string concatenation, insecure `postMessage('*')`, and open redirects with exact file and line citations).
- **Confirmed Decision 4 — Dark Obsidian Minimal Aesthetic**: Crafted with ReactBits-inspired micro-interactions—mouse-reactive spotlight cards, subtle radial-masked dot-grid canvas, smooth text reveal transitions, single-elevation hairline borders, and unboxed typographic metadata complemented by the official MLSA shield colors (`#0078D4` Azure & `#50E6FF` Cyan).
- **Confirmed Decision 5 — Evidence Drawer & MLSA KIIT Report Export**: Interactive slide-over Evidence Drawer displaying raw proof alongside copyable remediation snippets (Next.js, Vite/Express, Vercel/Netlify configs), plus one-click export of an official **MLSA KIIT Chapter Security Audit Report** featuring the MLSA emblem (Markdown, JSON, and print-ready certificate view).

## 1. Overview & Core Concept

- **What It Does**: Provides **MLSA KIIT Chapter** members with a unified security verification workspace where teams can enter a deployed project URL, connect a public GitHub repository URL, or drop source/`package.json` files to run a real-time, non-destructive security audit.
- **Target Audience / Persona**: Microsoft Learn Student Ambassadors at KIIT reviewing student hackathons, chapter web portals, full-stack apps, and open-source tools before launch.
- **Key Value**: Eliminates noisy, hallucinated, or generic security warnings. Every reported issue includes a cryptographic or structural proof artifact (the exact raw header, response snippet, CVE ID, or line-numbered code) and a framework-ready fix.

## 2. User Experience & Visual Design

### Key User Flows

1. **Target Configuration & Launch**:
   - The user enters a **Live Target URL** (e.g., an MLSA KIIT project deployment), a **Public GitHub Repository URL** (e.g., `https://github.com/owner/repo`), or drops/pastes source code and `package.json` manifests—or combines both for a full-stack audit.
   - Users can toggle which of the four audit engines to execute and immediately run the verification pipeline.
2. **Real-Time Verification Pipeline**:
   - As the backend executes each check, the interface updates with real execution timings (`tabular-nums`), showing each module's live progress and exact number of verified passes and findings.
3. **Findings Table & Passed Controls Ledger**:
   - **Verified Findings Tab**: Displays only confirmed vulnerabilities sorted by severity (Critical, High, Medium, Low), category, affected asset/endpoint, and CWE/OWASP mapping.
   - **Passed Checks Tab**: Explicitly lists every security check that passed (e.g., "HSTS Enforced", "No Exposed `.env` File", "0 Known CVEs in 18 Dependencies") so MLSA KIIT teams get credit for secure engineering.
   - **Raw Telemetry & Headers Tab**: Shows the complete, unedited HTTP response headers, TLS state, discovered scripts, and scanned file manifest.
4. **Exact Evidence Drawer & Copyable Fix Snippets**:
   - Clicking any finding opens the **Evidence & Remediation Drawer**, presenting:
     - **Authentic Proof Block**: Exact HTTP response headers, probed URL status + body verification, OSV.dev advisory JSON + fixed version, or line-numbered code snippet.
     - **Verification Command**: A copyable `curl` or reproduction check so any MLSA KIIT ambassador can independently verify the finding in their terminal.
     - **Copyable Fix Snippet**: Framework-specific remediation code (Express/Node, Next.js/Vercel, Nginx, or React patch) with one-click copy.
5. **MLSA KIIT Chapter Audit Report Export**:
   - Generates a structured **MLSA KIIT Security Verification Report** stamped with the official Microsoft Learn Student Ambassador shield emblem (`/assets/aistudio/image_950b45df.png`), project metadata, audit timestamp, executive summary, passed controls, and detailed findings with fixes—exportable as Markdown (`.md`), JSON (`.json`), or formatted print/PDF report.

## 3. Key Product Decisions & Trade-Offs

- **Decision 1: 100% Deterministic Inspection Over AI Guessing**
  - *Chosen Approach*: Server-side HTTP/TLS/CORS/Route inspection, live `api.osv.dev` CVE queries, and deterministic regex/AST source analysis with SPA fallback detection.
  - *Why*: Directly fulfills the requirement for **zero bogus or fake reports**. Every finding is backed by raw empirical data rather than probabilistic LLM speculation.
  - *Alternatives Considered*: Prompting an LLM to "guess" vulnerabilities from a URL or snippet was rejected because LLMs frequently hallucinate non-existent vulnerabilities or miss live HTTP configuration headers.
- **Decision 2: SPA Catch-All False-Positive Filtering in Route Probing**
  - *Chosen Approach*: Before probing sensitive paths (`.env`, `.git/config`, `package.json`), the server fetches a known non-existent random path (`/mlsa-kiit-nonexistent-check-<uuid>`) and compares status codes, `Content-Type`, and body signatures. A probed route is only flagged if it returns `200 OK` AND matches structural signatures (e.g., `KEY=VALUE` lines for `.env`, `[core]` for `.git/config`, valid JSON with `"name"`/`"dependencies"` for `package.json`, or `"mappings"` for `.map` sourcemaps)—never when an SPA router returns `index.html`.
  - *Why*: Student apps built with React/Vite/Next.js frequently serve `index.html` with `200 OK` for all unknown URLs; naive scanners falsely report `.env` exposure on every SPA.
- **Decision 3: Hybrid Server Proxy + Local Audit History**
  - *Chosen Approach*: Express backend routes perform cross-origin URL fetching, CORS reflection tests, GitHub repository tree/file retrieval, and OSV.dev batch queries; `localStorage` persists the user's recent MLSA KIIT audit runs for instant comparison and re-export.
  - *Why*: Browsers block direct client-side inspection of third-party security headers and CORS headers; running the inspection through the backend proxy captures every raw header accurately.

### Data Model & State

- **`AuditTargetConfig`**: Holds `targetUrl`, `githubRepoUrl`, `uploadedFiles` (array of `{ name, content }`), and boolean flags for the 4 audit modules (`httpHeaders`, `routeProbing`, `dependencyCve`, `sourceSast`).
- **`VerifiedFinding`**:
  - `id`, `title`, `severity` (`critical` | `high` | `medium` | `low`), `module` (`http` | `exposure` | `dependencies` | `sast`)
  - `cwe`, `owasp`, `affectedTarget` (URL endpoint, header name, package name, or `file:line`)
  - `summary`: Plain-English explanation of why this issue is exploitable.
  - `evidence`: `{ type, rawProof, reproductionCommand, verifiedAt }` — the exact empirical evidence proving the issue exists.
  - `remediation`: `{ summary, snippets: Array<{ label, language, code }> }` — copyable fix snippets.
- **`PassedCheck`**:
  - `id`, `title`, `module`, `target`, `proofSummary` (e.g., `Strict-Transport-Security: max-age=63072000; includeSubDomains; preload`).
- **`AuditReport`**:
  - Complete immutable snapshot of an audit run with `id`, `projectName`, `timestamp`, `durationMs`, `targetSummary`, `findings: VerifiedFinding[]`, `passedChecks: PassedCheck[]`, and `rawTelemetry` (response status, headers map, TLS status, scanned files list, dependency count).

### Interactive Component & State Mapping

- **Target Input & Quick-Test Presets**: Validates URLs and GitHub `owner/repo` paths, supports drag-and-drop or paste for `package.json` and source files (`.ts`, `.tsx`, `.js`, `.py`, `.env`, `.html`), and includes real working sample targets (e.g., auditing the current live app URL or loading a realistic vulnerable student project manifest/codebase for immediate verification).
- **Module Execution & Filtering**: Interactive segmented filter controls filter findings by severity (`All`, `Critical`, `High`, `Medium`, `Low`), audit module, or live search query, updating counts in real time with `tabular-nums`.
- **Evidence Drawer & Fix Copy**: Clicking any row opens the detail drawer with keyboard (`Escape`) and backdrop dismissal, framework tabs for remediation code, and instant clipboard copy with confirmation state.
- **Audit History & Report Exporter**: Saves completed runs to `localStorage`, allows switching between past MLSA KIIT project audits, deleting history items, and exporting the active report stamped with the official MLSA shield logo as `.md`, `.json`, or a clean printable certificate view.
